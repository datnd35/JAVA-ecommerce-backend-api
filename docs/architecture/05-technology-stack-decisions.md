# 05 — Technology Stack Decisions

Each row states the decision and the concrete justification; "N/A yet" means the decision is
explicitly deferred pending a product/infra answer, not silently assumed.

| Component                                 | Decision                                                                                                                                                                                                                                                      | Justification                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Language/runtime                          | Java 21 + Spring Boot 3.5.x                                                                                                                                                                                                                                   | Matches target project's existing `pom.xml` parent version exactly — no upgrade needed, no compatibility analysis required since we are _adding_ modules at the same version, not changing the existing ones.                                                                                                                    |
| Web                                       | Spring Web (MVC)                                                                                                                                                                                                                                              | Matches existing `myshop-module-manager` convention; no evidence of a need for reactive (WebFlux) given request volumes are unknown/unverified.                                                                                                                                                                                  |
| Persistence (new services)                | Spring Data JPA + Hibernate + PostgreSQL driver                                                                                                                                                                                                               | Open4Talk's real schema (UUID PKs, Postgres enums/arrays, 38 entities with relations) maps far more directly to JPA/Postgres than to the target's existing MyBatis-Plus/MySQL convention, which was built for an unrelated product-catalog domain. See `01-current-state-assessment.md §4` for the explicit Option A/B decision. |
| Persistence (existing `myshop-framework`) | Unchanged (MyBatis-Plus + MySQL)                                                                                                                                                                                                                              | Rule: do not change existing conventions without explicit justification; the product-catalog domain is untouched by this migration.                                                                                                                                                                                              |
| Security                                  | Spring Security + JWT (resource-server style)                                                                                                                                                                                                                 | Replaces NestJS Passport/JwtStrategy; default-deny filter chain fixes confirmed source gap (#3 in `01-current-state-assessment.md`). OAuth2/Clerk consolidation is **N/A yet** — pending product decision on whether to keep Clerk.                                                                                              |
| API Gateway                               | Spring Cloud Gateway — **conditional**                                                                                                                                                                                                                        | Only introduce if the deployment platform does not already provide managed routing/ingress with JWT edge-checks and WebSocket passthrough. **N/A yet** — deployment platform not yet decided for the new services.                                                                                                               |
| Spring Cloud compatibility                | If Spring Cloud Gateway is introduced, use the Spring Cloud release train compatible with Spring Boot 3.5.x per the official Spring Cloud/Spring Boot compatibility matrix (checked at implementation time, not hardcoded here, since matrix entries change). | Avoids guessing a version number now that may drift from the actual Boot patch version in use at implementation time.                                                                                                                                                                                                            |
| Sync HTTP client (service-to-service)     | Spring `RestClient` (built into Spring Boot 3.2+)                                                                                                                                                                                                             | No new dependency needed; avoids introducing Feign/WebClient unless reactive or declarative-client needs emerge.                                                                                                                                                                                                                 |
| Messaging                                 | RabbitMQ                                                                                                                                                                                                                                                      | Matches source's own recommendation (job dispatch + retry pattern fits BullMQ's actual usage better than Kafka's log/replay model); Kafka only reconsidered if event replay / long retention / many independent consumer groups becomes a proven requirement.                                                                    |
| Cache                                     | Redis — **only where a concrete cache need is identified** (e.g. `UserPromptCache`)                                                                                                                                                                           | Not introduced as a general-purpose queue substitute; queue role is RabbitMQ's, cache role is Redis's, per task instruction not to conflate them.                                                                                                                                                                                |
| Object storage                            | Google Cloud Storage client library                                                                                                                                                                                                                           | Matches confirmed source usage (avatars, media segments/manifests); no credential is copied into this repo — new service-account credentials must be provisioned fresh, never reusing the leaked key noted in source `07-technical-debt.md` issue #1.                                                                            |
| Search                                    | Elasticsearch client                                                                                                                                                                                                                                          | Matches confirmed source usage for transcript segment search; treated as a rebuildable read-model, not a system of record.                                                                                                                                                                                                       |
| AI providers                              | Direct SDK/HTTP clients for OpenAI, Anthropic, Azure Speech (evaluate Spring AI as an abstraction layer once provider set is finalized)                                                                                                                       | Spring AI not adopted immediately since the exact provider feature usage (e.g. Azure Speech's phoneme-level pronunciation scoring) may not be fully covered by a generic abstraction — **N/A yet**, revisit during AI Evaluation Service implementation (Phase 2/3).                                                             |
| Observability                             | Spring Boot Actuator + Micrometer + Prometheus + Grafana                                                                                                                                                                                                      | Directly reuses the target project's existing, working monitoring stack (`docker-compose.yml`, `monitoring/prometheus/prometheus.yml`, Grafana provisioning) — add each new service as another scrape target, no new infra component needed.                                                                                     |
| Distributed tracing                       | OpenTelemetry (Micrometer Tracing + OTLP exporter)                                                                                                                                                                                                            | Only needed once more than one service is actually deployed and a request can cross service boundaries — introduce starting at the phase where Media Worker or AI Evaluation is split out, not before.                                                                                                                           |
| Testing                                   | JUnit 5 + Testcontainers (Postgres, RabbitMQ) for integration tests                                                                                                                                                                                           | Mitigates the source's confirmed zero-test-coverage risk by requiring every migrated capability to carry its own Java test from day one, rather than porting the untested-behavior risk forward.                                                                                                                                 |
| Container orchestration                   | Docker Compose (extend existing file); **no Kubernetes, no Eureka, no Config Server**                                                                                                                                                                         | No evidence of a scaling/operational need that justifies this infra; task explicitly disallows adding it "because microservices." Revisit only if concrete multi-instance service-discovery need arises.                                                                                                                         |

## Explicitly rejected (unless new evidence emerges)

- **Kafka** — no confirmed requirement for event replay/long retention over RabbitMQ's simpler model.
- **Kubernetes / Eureka / Spring Cloud Config Server** — no confirmed multi-instance operational
  requirement yet; Docker Compose + externalized `application.yml` per service is sufficient at
  current evidence level.
- **Distributed transactions (e.g. Atomikos/XA)** — rejected per `04-database-and-event-strategy.md §8`.
